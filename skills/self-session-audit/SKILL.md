# 会话自检

读 DSH 的会话事件流，出三份报告：**操作**（做了多少、错在哪、哪里在重复）、**token**（贵在哪）、**skill 加载**（哪些真的生效了）。只读不写，不改会话文件。

## 跑

```powershell
<conda 根>\python.exe <本 skill>\scripts\session_audit.py
```

用**装了 `zstandard` 的解释器**跑：本机是 `<conda 根>\python.exe`（base）与 rag 环境，`multimodal` 里没有。

范围由脚本顶部的两个常量决定，不用命令行参数：`SESSION_ID`（空 = 最近改动的会话）、`TURN`（0 = 全部轮次）。

## 三份报告怎么读

1. **操作** —— 工具调用次数、真失败分类、非 0 退出单列、同名同参数重复调用、探针写删抖动。
2. **token** —— 「缓存读取 ÷ 模型步 = 每步平均上下文」。**步数是量级杠杆**：缓存读取 = Σ(每步上下文)，上下文单调增长，所以步数减半 ≈ 总花费掉到四分之一。改「少而大」比改「每次省一点」划算得多。
3. **skill 加载** —— 区分「正文真的进了上下文」与「只在目录摘要里出现过」。**后者等于没生效**：目录摘要在每个会话开头都有，不代表模型读了它。

## 两条读报告的纪律

- **非 0 退出里混着有意的红灯与管道无匹配**，必须人剔。「先红后绿」的测试失败是有效调用。
- **失败判定是文本模式匹配，会误报**：只要工具结果里**出现**该字样就算。最常见的两种——回读/grep 一个正文含该字样的文件（例如 `Select-String` 一份写着 `spawn EPERM` 的文档），以及本 skill 自己的报告被再次扫到。脚本已把沙箱那类限定为只看 `pwsh`、并排除自身的运行，但「打印出该字样」与「真的失败」在文本上无法区分——逐条看一眼再下结论。

## 返工归因

自检不止数数：把本轮的返工点按三类归档，下轮开工前先看这份归因。

- **环境**：服务没起或卡死、端口被占、沙箱拒写。判据：换台机器还会不会发生。
- **判据套利**：为过门禁牺牲质量（两行合成一行、删注释、关检查、把不通过的 `skip` 掉）。判据：指标好看了，读者更难看懂。
- **缺验证**：改完没跑就交付（改了共享夹具却没全量跑、声称绿了其实没跑）。

三类的修法不同：环境写进运行手册；判据套利改门禁的用法、或立一条规矩；缺验证改流程（先跑再交）。

## 完成标准

三份报告都打出来了，且第一份里**每一项真失败都说得出是「我造成的」还是「环境造成的」**；第三份里凡是「从未加载」的 skill，说得清是**本来不该加载**还是**该加载却漏了**。说不出就说明还没读透这份报告。
