# 单文件分阶段脚本

命中「写脚本、stepN、入口文件头、`data/`、运行上限」时读本文。风格与怎么跑见 [SKILL.md](../SKILL.md)；抽函数通则见 [function.md](./function.md)；多文件目录见 [project.md](./project.md)。

完成标准：每个数据跳一个 `stepN`；`__main__` 只编排、且在文件最末尾；参数硬编码；脚本自己带运行上限（默认 5 分钟，见「运行上限」）；输入在 `data/` 或 `data/source/`，产出在 `data/result/`，分步文件名与 `stepN` 同号。入口脚本模块 docstring 按「顶部注释」四层写（真·一步可压成开场 + 怎么跑）；原理编号与入口编号不混用。写分层文件头时对照本文末尾的完整范本。

## 何时用

**用**：目标已经说清（下哪本书、处理哪份 JSON、打哪条接口）；实现可以放进一个 `.py`；中间有真实的数据跳（请求 → 取字段 → 下一跳）。写或改入口脚本的文件头模块注释（顶部 docstring）时也读：分阶段脚本，以及多文件项目 `scripts/` 里跑完就退出的入库、评测、探测。

**不用**：FastAPI / 多文件服务的目录分层（见 [project.md](./project.md)）；纯工具函数集（没有「跑一遍」的流程）。真·一步脚本不切 `stepN`；只要写文件头，仍读下面「顶部注释」的压缩档。

---

## 顶部注释

文件开头的模块 docstring（`"""..."""`）是这份脚本的说明书。打开文件先读它，就能知道：干什么、顺着哪条链路、停在哪、拿什么当例子、从哪几个函数跑起来。

函数内部的 docstring、行内 `#`、怎么跑那几项字段名见 [SKILL.md](../SKILL.md)「全局规范」。本节只管文件头怎么分层。

### 读完文件头要能答的四件事

1. 这一份脚本干什么、明确不干什么。
2. 一条样本在系统里逐步发生什么；本脚本走到哪一步结束。
3. 用本文件会跑的输入，能看出「过 / 没过 / 过了但不够好」。
4. 从哪几个函数进、吃什么、要先起什么、吐什么。

### 四层，从上到下

缺一层就补。真·一步脚本把第 2、3 层压掉，只留开场和怎么跑。

**1. 一句开场**

干什么、停在哪、不干什么。一句到两句。指标定义不要写在这里。

**2. 原理（按系统流程）**

先写完整链路（线上或批处理里真实发生的顺序），再写本脚本每条样本走到哪、立刻判定、然后下一条。

正样本按发生顺序编号。负样本写「前几步相同，判法不同」，不要整段复制。

测到哪写到哪。没跑的阶段只在开场和停点各点一次。后面的生成、模型会不会只看前几条，都不是本脚本的测试目的，除非这份脚本真的跑了那一步。

**3. 例子**

用本文件常量里的真实输入（或即将写进去的样本），把原理走一遍。每条写清：输入 → 期望 → 一次实测的结果（换库或改参数会变）→ 算过还是没过。

例子只解释原理里已经出现的词，不另起概念。需要分清「过了但排位差」时，单独留一条这样的样本，不要把排位差说成没过。

**4. 怎么跑（本文件入口）**

列出职责、入口步骤、输入、前置、产出、对外函数（字段见 [SKILL.md](../SKILL.md)「全局规范」）。

这里的步骤编号是「打开这个文件从哪进」，和原理里「一条样本走的步」不是同一套。两套都从 1 数时，标题里写明「不是同一套」。入口步骤用一句话把函数名映射回原理编号（这个函数把原理第几到第几步跑完再判）。

### 骨架

按这个顺序写，不要把例子插到开场前面，也不要把怎么跑揉进原理。

```python
"""
一句：干什么、停在哪、不干什么。

原理（按系统流程）
  完整链路是：A → B → C → D。
  本脚本每条样本只走到 B 结束，立刻判，然后下一条。不跑 C、D。

  一条正样本逐步发生什么：
    1. ...
    2. ...
    3. 到此停止。看第 2 步之后的列表怎么算过。
  一条负样本：1～2 步同上；第 3 步改用另一套判法。

  例子（输入就是下面的常量；一次实测，换数据会变）
    「典型输入 A」→ 期望 … → 过 / 没过 / 过了但不够好。

怎么跑（本文件入口；编号和上面「一条样本」不是同一套）
  职责：加载同一份数据，把每条样本的原理前几步跑完再判，然后退出。
  入口步骤：
    1. 函数甲 — 读库或读文件，整个脚本只做一次。
    2. 函数乙 — 逐条把原理 1～N 跑完再判。
  输入 / 前置 / 产出 / 对外：…
"""
```

### 完整范本

下面是一份抽出来的完整四层 docstring。对照层次怎么叠、两套编号怎么分开。范本里的指标名、样本问句、一次实测名次只服务这份例子，不要抄进正在写的脚本。

```python
# 本文件不是可运行脚本。只收一份入口脚本顶部 docstring 的完整范例。
# 写分层文件头时对照四层怎么叠；正在写的脚本用自己的链路、样本、入口函数。

"""
最小评测口：顺着线上问答链路走到精排为止，看正确答案在不在精排结果里。精排之后的生成、引用、写答案都不跑。

原理（按系统流程）
  线上完整链路是：
    意图（分类 / 改写）→ 召回 → 精排（截成 TOP_K）→ 同节邻块 → 拒答或生成。
  本脚本每条样本只走到「同节邻块」结束，拿到一份和线上生成窗口同形状的命中列表，立刻判对错，然后下一条。
  不组提示、不调 Chat 写答案。所以测的是检索排位，不是模型会不会只看前几条、忽视后面。

  一条正样本（expect=hit）逐步发生什么：
    1. 意图：用户原话进改写槽（默认开），得到检索用问句。本脚本不跑闲聊分类，默认当检索题。
    2. 召回：向量 + BM25，RRF 融合后大约 20 条（candidate_n，不是最终给模型的）。
    3. 精排：从这约 20 条里截成 TOP_K 条，默认 5 条。重叠重排默认关，顺序保持召回融合序，只截断。
    4. 同节邻块：这 5 条里同一目录标题的邻段可能并进正文，条数可能变成 4（去重），不再从那 20 条里补人。
    5. 到此停止。看第 4 步之后的列表（下面叫「精排结果」，通常 5 条）：
       - 来源对，且 pages 与期望页有交集，算「这条是正确答案」。
       - 正确答案在精排结果的第 1 位 → Hit@1（同时也是 Hit@5）。
       - 正确答案在第 2～5 位 → 只算 Hit@5，打印「Hit@5 未进@1」。
       - 5 条里都没有 → Hit@1、Hit@5 都不过。
    6. 本脚本「通过」看 Hit@5。Hit@1 只打印。后面的生成步骤不进行。

  一条负样本（expect=refuse）逐步发生什么：
    1～4 步同上，同样得到精排后的几条。
    5. 不看来源和页。看这几条会不会触发拒答：列表空，或最好的向量余弦低于 REFUSE_MIN_SCORE。
    6. 过了 = 线上也会在生成前拒答。同样不写答案。

  例子（问句就是下面 SAMPLES；名次来自一次实测，换库或改写后会变）

    「后视镜怎么折叠」，期望页 93。
      召回约 20 条 → 精排 5 条 → 第 1 条就是第 93 页。
      → Hit@1。停，不生成。

    「后视镜如何展开」，期望页 93。
      同样精排第 1 条就是 93 页（折叠和展开在同一段）。
      → Hit@1。停，不生成。

    「车上那个镜子往里收」，期望页 93。
      召回约 20 条 → 精排 5 条。一次实测：第 1 条是第 360 页洗涤液，第 4 条才是 93 页。
      → 正确答案在这 5 条里，但不在第 1 位 → 只算 Hit@5。停，不生成。
      线上若继续生成，模型会看见全部 5 条；会不会只用第 1 条，本脚本不知道。

    「外面的镜子怎么折起来」，期望页 93。
      精排 5 条里一次实测第 1 条是轮胎段（约 361 页），第 2 条才是 93 页。
      → 仍是 Hit@5 未进@1。停，不生成。

    「红烧肉怎么做好吃」，expect=refuse。
      召回仍会吐约 20 条无关段 → 精排 5 条。一次实测最高余弦约 0.37，低于 0.4。
      → 应拒答且已拒。停，不生成。

    「Python 怎么读 JSON 文件」，同样 refuse。
      精排 5 条最高余弦约 0.40，仍低于阈值 → 拒。停，不生成。

    汇总 Hit@1=2/4 Hit@5=4/4 拒答=2/2 表示：
      四道后视镜题的正确答案都在精排 5 条里；只有两道排在第 1 位。
      两道题外话在生成前就拒了。

怎么跑（本文件入口；编号和上面「一条样本」的 1～6 不是同一套）
  职责：加载与问答同一份库，按 SAMPLES 把每条样本的原理 1～4 步跑完再判，然后退出。
        不是评测台，不生成。
  入口步骤：
    1. open_knowledge_base — 读 data/lancedb，整个脚本只做一次。
    2. step2_check_samples — 逐条：改写 → 召回约 20 条 → 精排截 5 条 → 同节邻块
       （对应原理正样本 1～4），再按 expect 判 Hit@k 或拒答（原理 5～6）。
  输入：下面常量 SAMPLES。hit 要 source、pages；refuse 只要 expect。
  前置：已入库；embed_server.py 已起。改写开时要 DEEPSEEK_API_KEY。
  产出：控制台汇总；召回调试仍写 data/result/qa/step2_hits.json（只留最后一条）。
  对外：_hit_at（来源+页是否算对）、step2_check_samples。
"""

```

## 脚本入口

- 运行参数放文件顶部常量区或 `__main__` 第一行（不用 argparse，见 [SKILL.md](../SKILL.md) S12）。
- `if __name__ == "__main__"` 只按阶段调用 `stepN_...`，不解析参数、不写业务细节。

```python
if __name__ == "__main__":
    COMIC_NAME = "书名"
    # 阶段0：network2 → api_host
    api_host = step0_resolve_api_host()
    # 阶段1：搜索 → path_word
    hit = step1_search_comic(api_host, COMIC_NAME)
    # 阶段2：comic2 → 简介、默认分组话数
    results = step2_fetch_comic_detail(api_host, hit["path_word"])
```

- 每阶段一行注释（做什么、产出路径）+ 一行调用。不要再包一层 `run()` / `fetch_all()` 把步骤藏进去。
- 步骤函数就写在本文件，按 `step0`、`step1`… 排。不要为了对齐「逻辑必须在 utils」而拆文件。

## 运行上限

一次运行默认最多 **5 分钟**：预估更久，先报给用户或主进程「预计 X 分钟」，得到同意再改上限常量。

- 装法：文件顶部 `RUN_LIMIT_SEC = 300`，`__main__` 第一行 `faulthandler.dump_traceback_later(RUN_LIMIT_SEC, exit=True)`——到点自己退出，并打出所有线程的栈（精确到行），不用等谁发现。
- 进度行加 `flush=True`：`exit=True` 是直接结束进程，缓冲里没 flush 的行会丢，而它们正是判断卡在哪一步的证据。
- 拉起的子进程要自己收：父进程到点自杀**不带走**子进程，杀掉直接子进程也**不带走**孙进程（都实测过）——`subprocess.run(..., timeout=N)` 只管一层，所以每个 spawn 点都要带上限；主动收用 `Popen.kill()` / `psutil`，`taskkill` 在受限沙箱里会被拒（实测 `ERROR: Access denied`）。
- 本机实测超过 5 分钟的：整库入库约 13 分钟；跑真模型的评测同理。这类先问再跑。

## 按真实数据跳切步骤

不要按「感觉上的函数粒度」切。一跳 = 一次请求或一次明确的数据变换，加上取字段、打印、本步产出。

- **一步一个 `stepN_xxx`**：一个 def 做完这一跳。函数在文件里按 0、1、2… 顺序排。
- **步骤内按执行顺序写**：先请求、再取字段、再打印/落盘。读一个 step 就能看懂这一跳。
- **步骤内注释写清数据流**：哪个 URL、吃上一跳哪个字段、吐给下一跳什么。`#` 怎么写见 [SKILL.md](../SKILL.md) S4 / S5。
- **日志前缀与函数同号**：`step2_...` 打印 `[阶段2]`，不要阶段号和函数号错位。

协议还没摸清时，先写 **探测脚本**（一个文件打一个 URL），不要一上来写总控。落盘见下节。

## 脚本里什么算无效封装

抽函数的一般规则见 [function.md](./function.md)（薄包装）。脚本里另外这几条会把流程写难看懂：

- 把同一步拆成 `fetch_x` + `download_one_x` + `download_selected_x`，主流程要跳三次才能看完
- `max_workers=1` 的线程池包一层 for 循环
- 同一步骤里若线程池需要 callable，用 **步骤内嵌套 def**，不要提升成模块级工具

可以留：被 **两个以上步骤** 真正调用、且规则固定的协议细节（共用 HMAC GET、设备指纹、统一的 HTTP 非 200 报错）。

## data/ 输入与产出

这一节是脚本级输入输出的**单一事实源**。多文件项目不套本节的 `data/source` / `data/result` 分法。

脚本同级建 `data/`。不要平行再开 `output/` 或 `analyse/output/`。

**输入**

- 只有一份源文件：直接放 `data/<文件>`。
- 多份源文件：放 `data/source/`。

**产出**

- 一律写 `data/result/`。
- 分阶段脚本每步若落盘：文件名 `stepN_<含义>.<ext>`，`N` 与函数 `stepN_...` 同号，print 写出的路径。
- 一步脚本只有一份结果：`data/result/<含义>.<ext>`。

打开 `data/result/` 应能看出哪一步写出了哪个文件。没落盘的步骤不必硬造空文件。

## 编号只对应一条有序序列

使用者按序号选择的列表（第 N 话、第 N 条）必须对应 **一条有序序列**。站点上并行的分类（默认话 vs 单行本 / 番外）不要加总后再从 1 编号。

## 日志

| 场景 | 示例 |
|------|------|
| 大步骤 | `[阶段2] 已写入 data/result/step2_detail.json` |
| 循环 | `[3/120] 条目名` |
| 结论 | `问 → 答 → ... \| 结论: xxx` |

用 print 还是 logger 见 [SKILL.md](../SKILL.md) S13。批量 HTTP 关闭 per-request 调试；循环内不 dump 完整 JSON。

## 批处理

循环处理多条时，一笔失败记入失败列表并继续下一条；整批结束打印成功数/失败数，并列出失败项与原因。
