# Python 项目的通用规则

新建或整理项目之前先读这一份：配置文件放哪、`.env` 放哪、`scripts/` 收什么、启动文件怎么命名、工具函数放哪。

项目怎么分层、目录树长什么样、接口怎么写、前后端同仓怎么放，见 [prd-fastapi.md](./prd-fastapi.md)。环境与依赖（conda 还是 uv、依赖写在哪）见 [env.md](./env.md)。调研用的最小服务见 [service.md](./service.md)；单文件脚本见 [script.md](./script.md)；函数与数据模型怎么写见 [function.md](./function.md)。**文档**（README、`CONTEXT.md`、ADR、`architecture.md`、`pipelines.md`、`todo.md`、最小视图）什么时候建、写在哪、怎么写，归项目文档规范——包括「放 `docs/` 不放仓根」，本文不再重复。

完成标准：新建或改目录时下面每条都套上。

## 何时用

**用**：新建项目、加模块、设计目录、整理已有仓、改目录。

**不用**：层与模块怎么切、接口怎么写、前后端同仓——见 [prd-fastapi.md](./prd-fastapi.md)。环境与依赖——见 [env.md](./env.md)。写或改任何一份项目文档——见项目文档规范。单文件脚本见 [script.md](./script.md)。只改函数内部、不改目录。只改通用风格 / 怎么跑，不动目录时。

---

## 通用规则

1. 项目的配置统一放在根目录的 `conf` 文件夹中，并按下面分类，不要混放。
   - 随运行环境变化、要从本机推算的值，放在 `conf/base.py`。例如项目根目录 ROOT：用 `Path(__file__).resolve()` 推算，不要把盘符写进 yaml。把仓库根加入 `sys.path` 也写在这里。启动文件和脚本引用这里的 ROOT，不要每个文件再写一遍。
   - 本服务的 host、port 直接写在对应的 `main.py` 或 `服务名_server.py` 里。本地不常改；生产放 Dockerfile。不要写进 `config.yaml`。
   - `conf/config.yaml` 只放各环境相同、属于本项目自己的公共常量，例如相对数据目录、模型目录名。不要放 ROOT、host、port、第三方地址、密钥。
2. 第三方对接配置和隐私配置统一放在根目录 `.env`；模板放根目录 `.env_example`。
   - 第三方对接：外仓 HTTP 地址这类对接参数。
   - 隐私配置：API Key、Token、填了密钥的别人家 `.env` 路径。不要写进 `config.yaml`，也不要在 yaml 里指向另一份带密钥的 `.env`。
3. 项目的层/模块测试文件，统一放在根目录 `scripts` 中。跑完就退出的入库、评测、探测也放这里；调研用的最小服务同样落在 `scripts/<名字>/`，形态见 [service.md](./service.md)。这些入口脚本的文件头怎么写见 [script.md](./script.md)。
4. 如果是单服务的项目，根目录启动文件统一使用 `main.py` 命名；如果是多服务项目，根目录放多个服务的启动文件，以 `服务名_server.py` 命名。启动文件只负责启动服务、写明 host 和 port、挂路由和生命周期。业务实现放在架构层或模块层目录里。不要用 `python 子目录/xxx.py` 启动产品服务。同一个进程不要在包内再留一份 `__main__`。
5. 只被一个模块使用的工具函数和 SDK，放在该模块目录里。被同一服务里多个架构层共用的，在该服务下建 `utils/`。纯 Python、没有服务文件夹、且被多个架构层共用时，才在仓库根建 `utils/`。被多个架构层共用的第三方 HTTP 调用，单独成模块，写法见 [third-party-http.md](./third-party-http.md)。
6. 开始写代码之前，先列出模块清单和每个模块所在的目录；之后加模块，放进已经定好的目录，不另起一套。
7. 新文件跟所在项目现有结构走。项目现有结构与规范不一致时先问，不按规范去改邻居文件。
