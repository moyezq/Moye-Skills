# 上线前审计

宣称「差不多了」之前整份走一遍。首次通常挂 5–10 条。

逐条判：✓ 观测正确、✗ 不符合、◯ 不适用。**A–G 的红项是发布阻断**，H 与 I 允许留尾。

## A 冷启动

- [ ] 热键唤起到窗口可见 < 200ms（热启动）/ < 600ms（冷启动）
- [ ] 内容出现前没有白闪或黑闪
- [ ] 窗口出现在正确的屏与位置，多显示器下开在活动屏
- [ ] 初始焦点落在最可能用到的输入控件上，用户能直接打字
- [ ] 正常启动过程中没有一闪而过的「加载中」
- [ ] 任务栏图标是自己的图标，不是框架默认图标
- [ ] 托盘图标跟随系统主题
- [ ] 全局热键首次启动即生效，不需要重启或重新注册
- [ ] 开机自启是用户主动勾选的
- [ ] 退出真的退出，没有残留进程

## B 窗口与焦点

- [ ] `Ctrl-W` 关闭窗口，`Win+↓` 最小化
- [ ] 点任务栏图标回到上次那个窗口，不是新开
- [ ] 窗口大小与位置跨启动记忆，多显示器时记住原屏
- [ ] 设置开独立窗口（`Ctrl-,`），不是主窗口里的模态
- [ ] 没有用 DOM 自绘的假模态；确认类对话框走系统对话框
- [ ] 全屏用的是系统全屏，不是最大化的窗口
- [ ] 失焦行为可预期且前后一致
- [ ] 自定义标题栏整条空白区都能拖窗口

## C 输入与光标

- [ ] 列表行、按钮、标签的光标保持不变
- [ ] 标签、标题、按钮文字不可选中；内容区与输入区可选
- [ ] 右键出的是原生菜单（或应用自己的动作菜单），不是浏览器的「重新加载 / 检查」
- [ ] 输入框外没有 I-beam
- [ ] chrome 上没有拼写红波浪线
- [ ] 拼音输入法正常：候选框贴着插入符，组字不丢字
- [ ] 日文假名与韩文各测过一次
- [ ] 主流程不用鼠标能完成
- [ ] 焦点环可见，样式跟系统一致
- [ ] `Esc` 在任何可关闭的东西上都有作用
- [ ] 列表里敲首字母能跳到匹配项

## D 视觉与材质

- [ ] 窗口背景用的是系统材质（mica / acrylic），不是一块静态色
- [ ] 窗口阴影与圆角由系统画，没有 CSS `box-shadow` / `border-radius` 冒充
- [ ] 透明区域的模糊正确透出
- [ ] 深浅色跟随系统，切换时不闪
- [ ] 强调色跟系统强调色，没有硬编码品牌色
- [ ] 界面文字用系统字体
- [ ] 对比度：正文与占位 ≥4.5:1，大字与控件 ≥3:1（浅深两套主题各自算过）
- [ ] 彩色底上的次要文字用同色相，没有灰字
- [ ] 动效尊重 `prefers-reduced-motion`
- [ ] 没有路由之间的淡入淡出

## E 滚动

- [ ] Win11 下用细滚动条；自绘的话滚轮、键盘、中键、拖拽选择都照常
- [ ] 程序化滚动没有用 `behavior: 'smooth'`
- [ ] 同窗口内导航后滚动位置保留
- [ ] 1000 项以上的列表做了虚拟滚动或分页

## F 性能与感知

- [ ] 空闲常驻内存 < 500MB
- [ ] 快速输入触发实时结果时没有掉帧
- [ ] 窗口最小化时 CPU < 0.5%
- [ ] 窗口隐藏时定时器与后台任务仍在跑（没有被节流到停摆）
- [ ] 网络超时 10 秒内给出用户可见的错误
- [ ] 超过 200ms 的操作都有加载态，200ms 内的都没有
- [ ] 展开 / 收起大列表没有可感知的顿挫

## G 系统集成

- [ ] URL scheme 全系统可用
- [ ] 文件关联生效，双击关联文件能打开应用
- [ ] 拖放收的是真实文件路径，资源管理器里拖进来正常
- [ ] 复制到剪贴板写全格式（纯文本 + RTF + HTML）
- [ ] 保存走系统保存对话框
- [ ] 通知走 Windows 通知中心
- [ ] 自动更新是真流程，不是「请去下载新版本」
- [ ] 崩溃上报接的是真服务，有符号化堆栈
- [ ] 单一实例：第二次启动聚焦已有实例
- [ ] 应用清单正确：标识符、版本、图标、文档类型

## H 无障碍

- [ ] Narrator 能走完整个界面
- [ ] 焦点移动有播报
- [ ] 对比度达 WCAG AA
- [ ] 系统字号放大到 200% 不破版
- [ ] Windows 高对比模式可用
- [ ] 所有动作都能不用鼠标完成

## I 审计怎么用

**五维评分**，每维 0–4：无障碍 / 性能 / 主题 / 自适应 / 实现完整性。总分 20：

| 分 | 档 |
|---|---|
| 18–20 | 优秀 |
| 14–17 | 良好 |
| 10–13 | 及格 |
| 6–9 | 差 |
| 0–5 | 严重 |

**严重度定级**：

- **P0 阻断**：任务做不完、数据会丢、状态显示错、路径不可达。
- **P1 重大**：含所有 WCAG AA 违规，发布前必须修。
- **P2 小**：不影响完成，但会被用户注意到。
- **P3 打磨**：细节不一致。

拿不准时问一句「用户会为这件事联系客服吗」，会就至少 P1。

**分诊顺序**（按这个次序修，不要按发现顺序）：

1. 断任务、丢数据、误导状态、不可达路径
2. 缺失的状态（loading / empty / error / disabled）
3. 流程与层级、自适应、跟系统不一致
4. 视觉与动效的不一致
5. 代码与素材清理

**认知负荷**按反模式逐条查：选项墙、记忆桥、隐藏导航、术语墙、视觉噪声、模式不一致、多任务要求、上下文切换。命中 4 条以上按高负荷处理，必修。

**可选的整体体检**：尼尔森 10 项按 0–4 打分，不适用的一项打 n/a 并从分母里去掉。多数真实界面落在 20–32 / 40。

**评审只看证据**：截图缺失、黑屏、名实不符时先重新取证，不要在坏证据上出结论。

**单条诊断测试**：把应用交给一个天天用 Windows、但没见过你这个应用的人，什么都不提示，看他第一次说「这有点怪」是在哪里。那一刻就是上面某一条。找到它，修掉，再发版。
