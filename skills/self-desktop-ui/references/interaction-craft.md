# 交互手感

动效、状态、文案、键盘、边界。桌面用户对「手感」的容忍度比网页低：他天天用别的 Windows 程序做对照。

## 动效决策链

按序问四句，任何一句答不上来就别加：

1. **该不该动？** 按触发频次判。键盘触发的动作一律不动——用户按得快，动画只会拖后腿。高频重复动作（列表里上下移动、连续切标签）不动。低频且有状态转移的（展开面板、切换到另一个视图）才动。
2. **解决什么？** 只有三件事值得动：说明刚才发生了什么（反馈）、说明东西从哪来到哪去（空间关系）、说明状态换了（转移）。说不出属于哪一类，就是装饰。
3. **什么曲线？** 自然减速用 `cubic-bezier(0.16, 1, 0.3, 1)`。`bounce` / `elastic` 只留给可抓取物（拖拽、甩动），不要当反射动作。
4. **多长？**

| 场景 | 时长 |
|---|---|
| 即时反馈（按下、悬停、开关） | 100–150ms |
| 常规状态变化（展开、淡入、颜色切换） | 150–300ms |
| 布局变化、浮层、视图切换 | 300–500ms |
| 刻意编排的登场（首次进入、完成时刻） | 500–800ms |

- **退出比进入快**。
- **产品界面里大多数过渡落在 150–250ms**。
- **桌面窗口与视图过渡可以放到 200–300ms**——比网页宽一点。太快的视图切换在桌面窗口尺寸下会显得闪。
- **不做整页加载编排**：用户不想看它加载。
- 平移距离控制在 10–20px 级别；只有同一列表里的多项同时出现才做 stagger，且总延迟要设上限。

## 只动什么

- **基础是 `transform` 与 `opacity`**。`width` / `height` / `top` / `left` / `margin` 交给布局引擎重排，会掉帧；要动尺寸就用 FLIP 或 `transform`。
- **`blur`、`backdrop-filter`、`clip-path`、`mask`、`shadow` 也在调色板里**，但限制在小区域（一个按钮、一张卡），别让大片区域每帧重算模糊。
- **`will-change` 只在已知动画期间挂**，常驻会占显存。

## 减动效

`prefers-reduced-motion` 设为 reduce 时：**减掉空间位移，保留透明度、颜色与状态反馈**。不是全关——用户要的是别晃，不是别反馈。

## 悬停按控件分档

桌面的高级感很大一部分来自悬停，但**分档处理**才是原生做法。统一给所有控件加悬停底色正是网页的味道。

| 控件 | 悬停 |
|---|---|
| 列表行、侧栏项、工具栏项 | 轻微背景色 |
| 普通按钮 | 不变（原生按钮悬停不变色） |
| 无边框的图标按钮 | 轻微背景色 |
| 内容里的文字链接 | 出现下划线 |
| 导航类元素 | 不做下划线 |

判据仍是「等价原生控件怎么做」。拿不准就对照系统自带的那个程序看。

## 按压态

**每个按钮都要有 `:active` 的凹陷**，跟悬停区分开。很多网页样式只写了 hover，按下去毫无反应——用户会以为没点上。

## 状态矩阵

每个交互组件齐备七态：`default` / `hover` / `focus` / `active` / `disabled` / `loading` / `error`（需要时再加 `success`）。

- **禁用态与遮罩层单独算对比度**，别以为主态过了就都过了。
- **`focus` 必须可见**，且与系统焦点环样式一致。

## 加载

按耗时给不同处理，跟网页的阈值不同——桌面程序 200ms 内的等待用户感觉不到：

| 耗时 | 显示 |
|---|---|
| < 100ms | 什么都不显示，结果到了直接上 |
| 100ms–1s | 转圈 |
| > 1s | 进度或分步说明，并说清在等什么 |

- **说出在加载什么**（「正在读取项目索引…」），不要只给一个转圈。
- **骨架屏只用在首屏数据密集且布局会跳动的地方**。原生程序的习惯是转圈，快速操作用骨架屏反而显得慢——占位块一闪而过，比直接出现结果更像卡了。
- **不要让加载态覆盖整个窗口**：局部加载就局部表示。

## 空态

**分型处理，别用一句「暂无内容」打发**：首次使用 / 用户自己清空 / 搜索无结果 / 无权限 / 加载失败。这五种该说的话完全不同。

- 说清**将出现什么**、**为什么值得**、**下一步做什么**（一个明确的动作或模板）。
- 桌面原生的空态偏简洁：一个图标加一行字。想讲更多就先按简洁写，再看是否真需要。

## 错误

每个错误回答三问：**什么失败了、为什么（已知且对用户有用时才说）、怎么恢复**。

- **不把内部错误码当主信息**；要给就放在可展开的详情里。
- **表单错误就近字段显示**，说清怎么改，不指责用户，保留已填内容，并向屏幕阅读器播报。
- **按状态码分别处理**：400 校验、401 登录、403 权限、404 未找到、429 限流、500 通用 + 支持入口。
- **超时 10 秒内给用户可见的失败**，不要让请求默默挂 60 秒。
- **组件级出错不阻塞整个界面**。

## 界面文案

- **控件说它做的动作**：「删除这 3 项」而不是「确定」；「保存更改」而不是「提交」。
- **错误说问题 + 恢复方式**，不是只说「操作失败」。
- **插件、权限、付费、删除、工作被堵的场合不讲笑话**。
- 破坏性动作的确认按钮写动作本身，让用户不用回头看正文。

## 键盘与焦点

- **全功能键盘可达**，Tab 顺序按视觉顺序。
- **`Esc` 在每个可关闭的东西上都有作用**。
- **浮层用 `dialog` 或 popover API**，让它可以逃出 `overflow: hidden` 的祖先；手写 portal 也行，别硬嵌。
- **模态内管住焦点**：打开时焦点进去，关闭时回到触发它的元素。
- **图标按钮要有可访问名**。
- **不用颜色单独传信息**，补文字、形状或位置。

## 中断与竞态

- **第二根手指落下不跳指针**；`pointercancel`、`lostpointercapture`、在窗口外松手、窗口失焦，四种情况都要清掉拖拽状态并释放捕获。清干净之后不刷新也能立刻再拖。
- **防双提交**：请求中的按钮进 disabled，不是靠文案提示。
- **乐观更新要能回滚**，冲突要有解。

## 长文本与本地化

- 单行 `text-overflow: ellipsis`，多行 `-webkit-line-clamp`，长英文单词 `overflow-wrap`。
- **flex / grid 子项加 `min-width: 0`**，否则长内容会把容器撑破。
- **文本容器不写死宽度**。
- **为翻译留 30–40% 膨胀**：德文、俄文比中文长得多，按钮会被撑开。
- 用逻辑属性（`margin-inline`、`padding-block`）给 RTL 留路。
- 数字、日期、货币走 `Intl` 格式化，不手工拼字符串。
