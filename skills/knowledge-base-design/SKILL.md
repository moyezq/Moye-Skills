# 知识库设计

**唯一事实源**：怎么读、怎么整理以本文件为准；形态与章节骨架见 `references/writing.md`。仓库根目录 `个人知识库文档规范.md` 仅为历史入口，不再维护细则。

完成标准：跳过规则已套；改到的每篇都过下面硬约束。新建或改结构时已 Read `references/writing.md` 全文；只改文风/精简时至少已读其「文风对照」，且宜列都过。一次改多篇且写法或目标还没对齐时，本轮只交一篇变更。

## 何时用

- 知识库设计、切篇、改词条结构
- 任务涉及笔记库里的 `*.md`，或用户未点名要读哪些库文件
- 批量整理、拆分、外链归纳、改文风/精简
- 新建库文档、改形态/章节框架
- 写库/框架用法文或入门文，或把课件/截图转成自有笔记
- 处理带 `> 外部文档` 的第三方总结稿（含库外同形态笔记）

命令与 conda 日探测见会话索引，不要在这里重跑。多文件 Python 项目目录见 `python-standard-coding` 的 `references/project.md`；`cases/` 命名见 `references/writing.md`；工程脚本见 `python-standard-coding` 的 `references/script.md` / `function.md`。

新建/改结构、不确定文首/概念/核心规则/用法对照/实战怎么摆时，**接着 Read** `references/writing.md` 全文。只改文风/精简、不改形态时，至少 Read 其中「文风对照」。只做外链收敛且不改结构、不改文风时，本节硬约束够用。

## 归纳日期与跳过

知识库 `.md` 在标题前写文档头。完整格式见 `references/writing.md`「文档头」。自有文至少一行 `> 归纳日期：YYYY-MM-DD`；第三方总结另加 `> 外部文档` 与 `> 来源：…`。每次归纳整理后把归纳日期改成当天。

| 条件 | 动作 |
|------|------|
| 归纳日期 == 今天，且用户消息**未**提及该文件路径、文件名或文档主题 | **跳过**，不 Read 全文 |
| 用户明确要修改、查阅、对比该文档 | **必读** |
| 无归纳日期行，或日期早于今天 | 不自动跳过 |

「用户提及」含路径片段、文件名、`Python Re` 这类主题词。跳过的是 Read 全文；Grep/Glob 定位不受限。

## 开场流程

1. Read 本文件（bootstrap 已做过则不要重读 bootstrap）
2. 需要「今日已归纳、可跳过」列表时，跑：

```powershell
python "<skill根目录>/scripts/list_today_notes.py"
```

3. 只 Read 用户点名或未命中跳过规则的文档
4. 本轮要新建/改写文档结构：再 Read `references/writing.md` 全文。只改文风/精简：Read 其中「文风对照」

## 整理时硬约束

### 外部文档

文首有 `> 外部文档`（或用户声明「第三方总结 / 不要改写」）时：不要按本库框架整篇改写、压缩、重排。必须保留 `> 来源：…`。无明确修改授权时正文接近原稿；允许补标识与来源、落位/改名、同步 `tree.md`、纠正明显 OCR/错别字。外部文档的正文已是入库知识，不要再当知识链消化一遍。

### 外链

- **资源链保留**（下载页、镜像、Releases、制品 URL、数据集页；含外部文档的 `来源`）
- **知识链**：有价值内容写入对应章节后再删链接与「参考资料」区；删前能回答「写进哪一节了」
- **样例 URL**（代码/表里的业务入口）不要当参考资料清掉
- **图床**：外站截图可改成文字说明后删除
- 抓取失败或没吸收：记为未归纳，不要空删

### 已验证步骤

有详细命令 + 文字说明、且实践跑通过的流程：不改写、不重排、不用知识框架整篇替换。仅明显错误做最小修正；更简便方法插在前面，不替换原文。

### 一文自洽与指针

- 单文件打开即可学完该标题主题；不靠「见某某.md」才能懂正文。
- **禁止跨文件夹引用**（跨笔记库顶级目录，如 `01-Python` → `05-Spyder`）。同目录、同案例包内互指尽量少；能并则并。
- 若必须跳到另一篇才能说明问题 → **划分不合理**：把缺的知识并进当前文，或拆成真正独立的主题文；不要用指针糊弄。
- 删指针前，有价值内容先对比写入目标文（纪律同「收敛」）。

### 多篇改写

一次改多篇、且写法或目标还没对齐时：先改一篇、列出本篇变更、等人看过再改下一篇。目标已经对齐的多篇可以同一轮改完。
正文不出现同系列其它文件名；切分只写在总览或 `tree.md`。
  ✅ 篇目和读者阶段已对齐 → 同一轮改该并走的相邻内容
  ❌ 切分未拍板就连改一整套编号文

### 拆分 / 迁出 / 改名

动手前列清：每块内容 → 目标路径；文件「留空」时注明未迁内容去向。库文档跟现有编号/目录，不要另建 `docs/` 堆官方全文。改完同步磁盘文件名、`tree.md`、仍指向已删文件的索引。大改优先可 git 回退。

### 收敛（防删知识）

1. 有价值内容先定目标正式文档，**对比并写入目标后再**从原文删或收窄。
2. 不要长期「待归纳 / 优化前全文」中间稿；本轮结束前必须并完或恢复。
3. 正式文档不要写改动留痕（「本文件只管…」「越界迁出见…」「优化前备份在…」）。过程留在 git / 对话。
4. 跨主题知识拆进对应库文档的案例节，不要用「杂烩 `.py` + 见某某脚本」代替归纳。
5. 薄目录 / 单点脚本能收成上级 `File.md` 或已有库文的，收完后删空目录。
6. 未获修改授权的外部文档正文不适用收敛/精简。

### 外仓 / 研究脚本

1. 先定知识主题再定路径。代码碰巧在 `Spyder/` 不代表笔记进爬虫。
2. 不要新建「工具链 / 脚本索引」式假案例；过时脚本直接舍弃。真正新工具才新建编号文，其余并进已有文。
3. 生产已验证路径与研究/深采分节，不要混成一条案例。
4. 案例目录英文名、脱敏：见 `references/writing.md`「案例目录」。

### 案例粒度与删档

多系统案例不要只留目录名 + 模式名表；每类写清代表 Host/path、关键字段、与邻类差异。流水线案例须写字段/列结构，不要只写「有某某文件」。薄 `utils/` 只有一两个原子文件时上移到案例根。

教学流水线（分块、抽点边、建图）的笔记要求见 `references/writing.md`「案例目录」。抽点边、建图、知识图谱 HTML 的案例脚本另 Read `references/graph-index-case.md`。

删外仓/留档前能回答：判断写进哪篇正式 `.md`；字段表是否进正文；可跑样例是否在库里或读者能按字段表重写；用户是否确认这是留档/可删。仍在管的生产仓不要擅自删。

### 主题、课件、改一处

- **标题定主题**，父文件夹只归档。一文件一主题；对照表只短引边界。生产 `.py` 落在实战节，不是整篇主题边界。同目录有范本时先 Read 骨架再写。
- 图片、课件、口播是**材料**：写成自有归纳文（仅归纳日期）。不要标 `外部文档`、`来源：某某.png`、「见同目录」、默认堆「做不到」当元叙述。
- 用户只说「改文首」或「改概述」：改完必须扫概念/对照/文末表，删掉与文首同义的重复。章节写什么见 `writing.md`「各层要求」；安装验收用业务命令（`xxx --version`），不要把 `where`/`which`/`env_detect` 写进读者向安装节。

文风、概念综览排布、库/框架入门骨架：见 `references/writing.md`。
