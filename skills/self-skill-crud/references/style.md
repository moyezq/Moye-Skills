# skill 文本规范

唯一事实源。写或改任何 skill 文本前读这一份。

## 一份 skill 的目录

```
<name>/
├── SKILL.md           必需：frontmatter + 正文
├── references/        按需读的文档
├── scripts/           确定性、可重复的活写成脚本
└── assets/            产出要用的素材（模板、图标、字体）
```

`scripts/` 里的代码不占上下文就能跑。同一段代码在几个路径里各被重写一遍，就是该收进 `scripts/` 的信号。

## 放哪一层

三种内容，按 agent 多快需要它排序：

1. **正文步骤**：agent 做什么，按序。
2. **正文参考**：同层平级的规则集合（一次复盘的每条规则同档），按需查。
3. **推到单独文件**：只有部分路径需要的细则，靠指针够到。

`SKILL.md` 正文控制在 500 行内；逼近上限就往下推一层，并在正文写清「什么时候去读哪一份」。超过 300 行的参考文件加一份目录。

**逐层往下推**主要不是省 token，是保住顶层的可读层级：不分层，正文会长到注意力摊薄——哪怕每行都活着。判据是分支：每条路径都要的放正文，只有部分路径需要的推下去。

**相关的放一起**：一个概念的定义、规则、坑放同一标题下，读一处带出邻居。

## 指针怎么写

**指针** = 一句话点名一份正文外的材料，并带上「什么时候去够它」的条件。skill 的 description 是一个，正文里点名某文件的一行也是。

指针的措辞决定 agent 何时、多可靠地去够它。必须有的材料配一句弱措辞的指针 = 行为方差 bug：先改措辞，改不动就把材料内联。

指针常驻，每个字每轮都在花钱，比正文更该剪：

- 领头的词前置——指针就靠它在触发。
- 一个分支一个触发条件；同义改写的两个分支合并成一个。
- 正文已经交代过的身份，指针里删掉。

## 步骤与完成标准

每个步骤终于一个**完成标准**：写清干完的条件。两个性质让它成为杠杆：

- **清晰**：agent 分得清「完成」与「未完成」吗？边界模糊（「理解达成」）会引来抢跑——它自己宣布做完了。先打磨边界（局部、便宜）；边界确实无法更清楚、又观察到抢跑时，才靠拆分序列把后续步骤推出视野。
- **要求**：要高。「每个改动都被覆盖」逼出彻底，「产出变更清单」不会。要求写进动词里（「逐条核对」「扫全仓」），别单列成一步祈祷。

最强的完成标准既可核查（能数、能比）又穷尽（覆盖全部对象）。

## 正文怎么写

- 每条交代齐四件，缺一件就没写完：**什么环境**（沙箱模式、目录、服务在不在）→ **什么场景**（哪个操作会碰到它）→ **做什么** → **最短步骤**（照着敲就能做完）。判定：把这条单独抽出来、没有上下文，照着做也对。
- 理由压成同一行的半句，不单独起段落、不挡在动作前面。正文里出现「视情况」「注意」「小心」，就是环境和场景还没交代清。
- 用**命令式**：写 agent 要做的事，不写它「应该考虑」的事。
- **解释为什么**，少堆 MUST / ALWAYS / NEVER。全大写强调是黄牌——它说明理由还没说清。理由说清了，模型在没预料到的情形里也能做对。
- 保持通用，别贴着某次对话的例子写窄了。
- 先写草稿，再用新眼睛过一遍。
- 定输出格式给**确切的模板**（套骨架比描述形状可靠）；给**示例**时标清输入与输出。

## 锚词

**锚词** = 模型预训练里已有的紧凑概念（_侦察兵_、_战争迷雾_、_曳光弹_），在正文里当词反复出现，用最少的 token 锚住一整片行为。它出现一次，agent 就够到同一片行为；同一个词出现在 prompt、正文、代码注释里，agent 会把它们连起来。

找机会把三处复述压成一个词：绕圈描述同一个要求的那一段，就是要坍缩的地方。

自己造词也可以，但造词不招募预训练的先验：预训练白给的东西，你得用定义 token 付。

## 剪枝

- **单一事实源**：一个含义只在一处权威。重复花维护与常驻成本，还把含义的层级地位抬过它真实的档位。（锚词是反面：故意重复 token，从不重复含义。）
- **结构图也算含义**：同一套「谁包含谁」的树或梯子，全文只出现一次。目录区与文末各画一张同义的图 = 剪枝失败。
- **环境也是事实源**（`--help` 输出、配置文件、目录布局）：复述它的正文是缓存，只在查起来贵时才配存在——写不成文的约定、选择背后的理由、配置不肯说的坑。
- 每行查**相关性**：它还承担这份文档的职责吗？没有剪枝纪律，默认结局是陈旧层越堆越厚，直到要钻穿它们才找得到还活着的部分。
- 逐句猎**废话指令**：模型默认就会照做的指令，花了常驻成本换零行为改变。判据是「改不改默认行为」，相对模型、不相对读者。一句失败就整句删，不要只删几个词。
- **否定句**把被禁的行为拖进上下文，反而更可及。写目标行为（「写一行注释」），被禁的那个字就不必出口。禁令只在无法用肯定表述的硬护栏处才留，且旁边配一句肯定目标。

## 安全边界

skill 里不放恶意代码、漏洞利用代码，或任何能危及系统安全的内容。按描述交代清楚的意图之外不做意外的事：不写误导性 skill，不协助未授权访问、数据外泄。角色扮演之类的正常用途不受此限。

## 对用户怎么说话

用户对术语的熟悉度差别很大。默认按「受过基本计算机训练」写；要直接用「JSON」「幂等」这类词，先确认对方懂，否则顺手给一句短定义。拿不准就解释一句，这不花什么。

## 改动怎么给人看

改完 skill 文本，给用户看的永远是三行：

1. **改前** —— 原文；原来没有这条就写「原来没有」。
2. **改后** —— 新文。
3. **为什么** —— 它挡住的是哪一步具体动作。

禁行号、禁黑话、禁「重构了 X」「优化了 Y」这类没有指认对象的说法。改动多时只给「摘要 + 要你拍的点」，全文让人自己开文件看，不整篇贴进对话。

为什么：人要看的是「这段值不值得留」，不是「改了几处」。行号是给子代理对证据用的坐标，人读它得多跳一次；黑话逼人先学一套词表才有资格判断，等于把成本转回给人。
