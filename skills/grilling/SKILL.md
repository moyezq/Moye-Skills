# 拷问式访谈（grilling）

无休止地拷问用户，直到达成共享理解。把主题画成一棵 **设计树**：每个决策分出挂在其下的子决策。

## 何时用 / 何时不用

**用**：动手前对齐——爬虫目标（下什么/存哪/去不去水印/番外怎么编号）、脚本形态（单文件还是小服务）、方案选型、字段命名。用户想被压力测试，或触发词含「拷问 / 盘问 / 先问清楚 / 对齐」。

**不用**：纯事实查询（直接查）；已经对齐、只剩执行的任务；用户已明确「直接做」且无分支待定。

## 按轮次推进

把树按 **轮次** 处理。**前沿（frontier）** = 所有「前置已解决」的决策，也就是现在就能问、不用猜答案的问题。一轮把整个前沿一次性问完：给每个问题编号，并附上你的推荐答案。等用户回答后再进下一轮。

一轮的格式：

```
❓ **Q1** - **<问题标题>**：<问题正文，可多段，可含多个选项>

➡️ <你的推荐答案>

---

❓ **Q2** - **<问题标题>**：<问题正文>

➡️ <你的推荐答案>
```

用户每轮的回答会重塑树：已解决的决策把前沿往外推，解开依赖它们的后续问题；重新计算前沿问下一轮。**答案依赖本轮其它问题的，属于后面轮次，不要本轮就问。**

## 分工：事实归 AI，决策归用户

**查事实是 AI 的活**，永远不该让用户去查。前沿问题若需要环境事实（文件、工具、接口），派后台 subagent 或用工具去查，别问用户任何你自己能查到的。不阻塞：正在查的是一颗「未解决的前置」，只有它下游的问题等它出结果，其余前沿照问。

**决策归用户**：把每个决策摆到用户面前，等答复。

## 结束条件

前沿为空、设计树每个分支都走完、没有任何东西被静默假设时，本轮访谈结束。在用户确认达成共享理解前，不要开始动手。
