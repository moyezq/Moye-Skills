# 开发经历抽面试题

从本轮对话或改动里抽出以后还会被问到、排障还会碰到的情况，写成面试问答。

---

## 何时用 / 何时不用

**用**：用户要把这轮开发、排障、对照开源的收获记成面试题。

**不用**：

- 记本仓为什么选这个开关、文件放哪 → 写 `CONTEXT.md` / `docs/adr.md` / `docs/architecture.md`
- 写 笔记库 主题文 → 知识库文档
- 动手前对齐需求 → 拷问式访谈

---

## 一条题长什么样

题干问**机制**，不问本仓现状。没见过这个仓库的人，拿着题也能答。

每题四段，段与段用标题隔开：

```
## {一句话题干}

### 问题背景
什么场景会碰到；面试或线上会怎么问。

### 原因
机制上为什么会这样。

### 解决方案
通用做法，换项目仍成立。

### 这样做的目的和效果
解决哪一类失败；付什么代价。
```

---

## 选题

从本轮抽出**可迁移的机制**，不是工作日志。

**留下**：换项目仍会被问到的机制。例如两阶段窗口切在哪一层、两种分数能不能比、评测窗口是否对齐生成窗口。

**丢掉**：本仓开关名、ADR 编号、仓库路径、只对这份样本成立的数字。

检验：删掉项目名后，题还是一道完整面试题。过不了就丢掉或改写成机制题。

条数跟本轮真正碰到的机制走，宁少勿凑。

---

## 步骤

1. 扫本轮：对话结论、代码改动、被用户纠正过的理解。
2. 按「选题」滤成机制清单。每条用一句话当题干。
3. 逐题写四段。方案段写通用解法；本仓如何落地不写进题，已有 ADR / 蓝图即可。
4. 落盘。根 README 或蓝图若已有「面试问答」指针，保持一行，不把题干抄进指针。

聊天里只报：写了几题、落在哪。不要把全文再贴一遍。

---

## 落盘

用户指定了路径就用指定路径。

否则写入当前项目 `docs/questions/README.md`：

- 文件头用两三句说明这是面试题，不是蓝图。
- 已有同题则改那一题，不平行再写一篇。
- 目录没有就建。不写进 `docs/adr.md`，不写进 笔记库。

落盘用正常书面语，短句、一段一事。不套回复压缩口吻。

---

## 完成标准

- 每题都有题干和四段，段与段有标题隔开
- 题干不含本仓开关名、仓库路径、ADR 编号
- 方案段换一个同类系统仍能用
- 文件已写到落盘路径
