# 根目录 README.md 写法（给人读）

写或改仓库根 `README.md`、或用户嫌 README 难读时读本文。  
建/读/改时机见 [DOC-MAP.md](./DOC-MAP.md)「README.md」。  
Python 仓目录怎么摆见主文件邻域入口；**人读 README 的结构与禁区以本文为准**。

完成标准：读者只靠 README（不必点开 `docs/`）能 clone、装依赖、跑通最小路径，并知道完整能力还缺什么；文中无「设计原型」式 docs 索引表。

---

## 读者与边界

README 给**人**上手跑项目。`docs/`、`CONTEXT.md`、`AGENTS.md`、ADR 给协作与自动化——不在 README 里当导航表罗列。

✅ 目录树末行：`docs/  # 内部说明，日常使用不必读`  
❌ 开篇「设计原型」下列一串 architecture / adr / RUNBOOK / EXTENDING 链接

---

## 推荐主线

按序写（可少不可乱序揉段）：

1. **定位**：项目名 + 一行做什么 + 可选能力短标签  
2. **页内目录**：介绍 · 快速开始 · 怎么工作 · 接口（若有）· 项目结构  
3. **项目介绍**：场景一两段 +「包含什么」表（能力 / 做什么 / 缺了怎样）  
4. **快速开始**：分阶——Ⅰ 最小可跑 → Ⅱ 配齐完整能力 → Ⅲ 试用  
5. **怎么工作**（可选）：短流程（可用 Mermaid）+ 关键开关/契约表  
6. **接口用法**（有 HTTP 时）：端点表 + 可复制的 `curl` 或等价示例  
7. **项目结构**：`├──` 树，每项一句

✅

```markdown
## 快速开始
### Ⅰ 安装并跑通核心
…
### Ⅱ 配齐扩展（推荐）
…
### Ⅲ 在界面里试一次
…
```

❌ 并列「配置 / 后端 / 前端 / 一键启动 / 系统依赖 / 使用说明」多节重复同一套步骤

## 硬规矩（对 / 错）

### 自洽：关键用法写在正文

开关矩阵、入口 URL、关键环境变量名、最小 `curl`/命令示例写进 README。

✅ 文内表格写清「看图要 `ocr` 且 `llm`」并给一条 `curl`  
❌ 「字段见 docs/API.md」「验收见 docs/RUNBOOK.md」代替正文

### 扩展：写清「缺了缺什么」

需要额外配置才能完整的能力，用「配好了能做什么 / 没配时」表述，不写成可有可无装饰。

✅ `| OCR | … | 读图必需。没有则图片几乎只剩元信息 |`  
❌ `| OCR | 可选扩展 | 有则更好 |`

### 远程与事实

远程仓库写**当前真实 clone URL**；变了再改。生产/本地入口写真实地址。

✅ `远程仓库：https://gitee.com/org/repo.git`  
❌ `GitHub：无（当前远端在 Gitee）`

### 健康检查与调接口

健康检查、试接口：浏览器打开文档/健康 URL，或 `curl`。

✅ `打开 http://127.0.0.1:8020/docs`  
❌ 把 `Invoke-WebRequest …` 写成项目标准调试姿势

### 结构用树

✅

```text
myapp/
├── start.py
├── backend/
└── frontend/
```

❌ 扁平「路径 + 说明」长列表，或再贴一张 import 链当结构

### 删重复与实现废话

与上文已写过的入口 URL、步骤不要再写「确认」段。代理、中间件等实现细节不进 README。

✅ 生产信息表里已有健康检查 URL → 启动节不再抄一遍  
❌ 启动后再贴一段 PowerShell 健康检查；或「前端把 `/api` 代理到后端」类实现说明

### 不写进 README

- 未验证方案、对照实验清单 → 计划类文档  
- 会随需求常变的前端交互边界 → 有则 `DESIGN.md` / 目标架构文档  
- 术语定义、ADR 全文、给 AI 的禁令 → 各自文件，README 不索引

---

## 落笔步骤

1. 认读者路径：最小可跑要几步；完整能力还要哪几步。  
2. 按「推荐主线」起草或改写；能合并的重复节删掉。  
3. 对照本文硬规矩逐条过一遍（尤其：无 docs 索引表、扩展表述、远程 URL、健康检查方式、树形结构）。  
4. 自己当陌生人扫一遍：只读 README 能否跑通 Ⅰ；能否看懂 Ⅱ 为什么重要。

完成标准：第 3、4 步无未改问题；无指向 `docs/*` 的「详见」代替正文的关键步骤。
