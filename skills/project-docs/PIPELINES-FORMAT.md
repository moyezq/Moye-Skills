# pipelines.md 格式

`docs/pipelines.md` 写**项目主流程的实现细节**。给开发者和 Agent 快速掌握：各层、各模块、各方法里真正要紧的怎么做。

不是核心功能清单（那是 `architecture.md`），不是「为什么这样选」（那是 `adr.md`），不是怎么安装（那是 `README.md`）。

## 何时建

主流程已经能按层/模块分开讲，且这些细节若写进 `architecture.md` 会把它撑成实现手册时再建。

单文件脚本、还没有稳定主流程时不建。

## 写什么

按主流程从上到下：每一层一句职责，下面是该层各模块（或各方法）里**改代码时必须知道**的判定、上限、字段落点、失败怎么走。

✅ 这份 PDF 无文字层时渲染哪几页、命中哪个上限名  
✅ 判型顺序是文件头 → 扩展名 → Content-Type，ZIP 往里看一层落到哪种格式  
❌ 把 architecture 的模块树再抄一遍  
❌ 把 `.env.example` 或 OpenAPI 再抄一遍  
❌ 已废的接口名、迁移对照、「原来/现在」对照表

开头只说本文干什么。用现在的模块名和路径，不用已废叫法。

## 同一轮改

本轮改了某层某模块的关键判定、上限或字段落点，同一轮改对应段落。不要让 pipelines 和代码各说各的。
