# ADR 格式

现在为什么这样选写在 **`docs/adr.md`**：一份文件，按 `ADR-NNNN` 编号，每条带日期。不要建 `docs/adr/` 目录，不要一决策一个文件。

被取代或废弃的决策从 `adr.md` **删掉**（编号不复用）。那次改动记入 **`docs/HISTORY.md`**，按时间追加。

两条都用到再建：第一条值得记的决策时建 `adr.md`；第一次废决策时建 `HISTORY.md`。

现行约束不在 ADR 里：目录位置、明确不做、步骤按 `docs/architecture.md` 执行；本仓 AI 禁令按 `AGENTS.md` 执行。`adr.md` 只回答「现在为什么这样选」。`HISTORY.md` 只在问「为什么曾经那样 / 要不要恢复旧决策」时读。

## adr.md 模板

```md
# 架构决策（现行）

现行约束在 [architecture.md](architecture.md) 与 [AGENTS.md](../AGENTS.md)。本文只记仍有效的为什么。废决策见 [HISTORY.md](HISTORY.md)。

## ADR-0001 · YYYY-MM-DD · {短标题}

{1-3 句：背景是什么、决定了什么、为什么。}
```

就这些。一条可以只有一段。价值在「**现在**做了某个决策」和「**为什么**」。

日期是该条**最后一次重写**的日期。改细节则重写该条并改日期，不要另开编号。

## 可选：现状句

只在决策没变、实现进度还值得记时加一行 `现状：…`。只写做没做完。不要写新选定，不要写新禁令。

## HISTORY.md

按时间追加。每条说明一次被取代或废弃的改动，五段都要有、每段一两句：

- **背景**
- **原因**
- **做法**
- **意义**
- **废弃原因**（含后继 `ADR-NNNN`，或「废弃无后继」）

不把旧全文抄进来。全文留 git。

## 编号

扫 `docs/adr.md` 里已有的 `ADR-NNNN`，取最大编号加一。已删编号不复用。

## 何时重写、何时新编号、何时进 HISTORY

- **同一条决策**改目录位置、默认值、实现：重写该条，改日期。
- **新的值得记的问题**：新编号，追加在 `adr.md` 文末。
- **整条作废或被另一条完全取代**：从 `adr.md` 删掉；`HISTORY.md` 按时间记一条；新为什么写在后继 ADR（可新建，也可并进仍活着的那条）。

## 自我更新完成标准

本轮代码或新 ADR **推翻**了某条决定，同时做完才算完成：

1. 旧条已从 `adr.md` 去掉，或已重写成当前为什么。
2. 若是取代或废弃：`HISTORY.md` 已追加。
3. `architecture.md` 已改。
4. `AGENTS.md` 若引用了旧规则，也已改。

只加新条、或只改进度说明，不算完成。

## 何时建议记 ADR

三条同时成立才记：

1. **难逆转**：日后改成本有意义
2. **没上下文会费解**：未来读者会看着代码想「为什么偏要这么做？」
3. **真实权衡的结果**：有真实备选，为具体理由选了其一

好逆转就跳过；不费解就没人会问；没有真实备选就只剩「做了显而易见的事」。

### 什么值得记

- **架构形态**：「用 monorepo。」
- **上下文间的集成模式**：靠领域事件通信，不走同步 HTTP。
- **带锁定的技术选型**：换掉要花一个季度的库、总线、鉴权、部署目标。不是每个依赖。
- **边界与范围**：「不做什么」和「做什么」同样值钱。
- **对显而易见路径的刻意偏离**：合理读者会假设相反的任何事。
- **代码里看不见的约束**：合规、合作方契约。
- **不明显的被否备选**：否则半年后有人又提被否的那个。
