# engineering.md 格式

`docs/engineering.md` 记本仓业务流程里真实踩过的工程问题。一条一个完整事件，问答呈现。

不是 ADR（现在为什么这样选），不是 history（过时决策），不是 README（怎么跑），不是给 AI 的禁令。通用规范已经写成 skill 的写法，不在这里再记一遍。

## 何时建

**建**：本仓出现过至少一条真实工程事故，且这条事故的判据还不在通用 skill 里。

**不建**：为了完整而建空文件；把 README 章节、ADR 形态、启动入口命名、配置按变化原因分类这类通用规范再抄一遍。

## 必有形

开头一两句：本文干什么。下面是问答目录，再按条写。条与条之间用分隔线断开。

每条固定五小节，标题不要另起一套：

1. 二级标题是问句
2. 出了什么问题
3. 当时的情况
4. 为什么会这样
5. 试过哪些办法
6. 最后怎么解决

✅

```md
## 1. 项目换个目录，配置就全乱了？

### 出了什么问题
仓一挪位置就找不到数据和密钥。

### 当时的情况
开发初期把路径和密钥写散在入口和 yaml 里。

### 为什么会这样
当时没当公开仓，没按「为什么会变」拆配置。

### 试过哪些办法
全塞进一份 yaml；用环境变量去读另一个仓的密钥文件。

### 最后怎么解决
根路径本机推算；监听地址写在启动文件；相对目录进仓内 yaml；密钥只读本仓密钥文件。
```

❌ 面试题结构（问题背景 → 原因 → 解决方案 → 目的和效果）；或再讲一遍「启动文件放仓库根」。

## 收什么

收本仓主路径上真实发生过的事故，写清后来定在哪个本仓文件。

不收已经由通用 skill 规定的写法。

完成标准：每条能单独当一个事件读完；目录里没有「通用规范还没定论所以写乱了」这类条目。
