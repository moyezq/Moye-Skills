# todo.md 格式

`docs/todo.md` 记本阶段打算做的方向。打开要能看见现在可能干什么。

不是工单（不写验收、不写方案），不是 `architecture.md`（不做 / 暂时不做 / 以后不写这里），不是 `engineering.md`（已踩过的坑不写这里）。

## 何时建

**建**：已有 `architecture.md`，并且出现第一条本阶段打算做的方向。

**不建**：还没有目标架构；为完整而建空文件。

## 必有形

开头写清：本文只收本阶段开放项；「下一步」由人点名；Agent 未点名不按清单改代码。

下面固定四节，标题不要另起一套：

1. 下一步（人点名，最多 3 条）
2. 业务流程待完善（主路径已有，质量或闭环不够）
3. 功能开发未实现（目标态有、代码没有或仍是预留）
4. 项目缺陷未修（已实现的行为不对或不可用；测试与卫生也归这里）

不要再开「工程卫生」第四节。不要把明确不做、暂时不做、以后再做抄进来。

一条一行，勾选列表。方向或目标即可；缺陷在哪可以还没钉死。

✅

```md
# todo

本阶段打算做的开放项。明确不做、暂时不做只看 `architecture.md`。
一条一行：方向或目标即可。不写验收、不写方案。
「下一步」由人点名（最多 3 条）。Agent 未在对话里被点名，不得按本文件改代码。
Agent 可以：勾选已完成、在对应节补可能的后续方向。改已有措辞或删行先问。已勾的定期清掉。

## 下一步

（空：等人点名）

## 业务流程待完善

- [ ] 主路径一次请求还要打多次外部接口，希望收少

## 功能开发未实现

（空）

## 项目缺陷未修

（空）
```

❌ 把「明确不做 / 公开后可做」写成两大节；或一条里写改哪些文件、用什么命令验收、和架构「暂时不做」对着干的方案。

## 人和 Agent

「下一步」只由人点名。未在对话里被点名要做的那一条，不按本文件改代码。可以读完后建议把哪句放进「下一步」，或建议新方向。

允许不先问：勾选已完成的项；在三类节里补一句可能的后续方向。

改已有措辞或删行先问。已勾的定期清掉。

项目若有 `AGENTS.md` 且写了更严禁令，听那一份。

用户打了 `/plain-todo` 或说「一项一项做」：仍先等人点名「下一步」或点名某一句，再只做那一句。

完成标准：人 10 秒内能看出「下一步」有没有点名；清单里没有不做/以后；没有未点名就开始改代码。
