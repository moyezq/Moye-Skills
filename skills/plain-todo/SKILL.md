# 白话待办：一项一项做

动手前对齐需求用 `/grill-with-docs`。本 skill 管另一段：**清单已有，按项讲清再执行**。

## 何时用 / 何时不用

**用**：仓库里已有 `TODO.md`（或用户点名的待办清单）；要一项一项推进；要先听懂再改。

**不用**：还没对齐要做什么（先 grill）；闲聊或只要查事实；用户已明确「直接改某某文件」且无需再解释。

---

## 流程

每进入本模式，或做完一项还要继续时，按序做。完成标准写在每步末尾。

### 1. 认清单

读项目根 `TODO.md`（用户另指定路径则读指定文件）。标「待裁决 / 待你拍板」且尚未拍板的项，本轮不排进「可做」。

完成标准：能指出清单路径，并列出让用户选的下一项候选（默认挑可直接做的）。

### 2. 解释当前这一项（必做，先于改代码）

只用大白话三块；用户要深挖再展开原理。完成标准：读者不查术语表也能说出「现在怎样、动哪里、修好什么」。

1. **原来什么样** — 现在实际怎么走（可用简单流程图）
2. **想改哪部分** — 动哪一层；什么不动
3. **改完解决什么问题** — 改前的痛点一句话 → 改后多挡了什么

```text
✅
原来：上传时只看「声明有多大」；没声明就先整包接下来，再在后面查大小。
想改：最前面那一层——没声明时也边收边数，到上限就停；后面已有的边写边数不动。
改完：大文件在写满临时目录之前就被挡住。

❌
本项属入口层资源防护：声明预检与分块上传下的累计读取封顶成对出现，
与下载层某条决策同源；反代体积上限与中间件互补……
```

先写大白话；术语必须出现时，白话在前、括号里再给术语。不先讲「原理框架 / 和某某模块同类」。

写完后停住，等用户说做 / 换一项 / 先不定。

### 3. 只做这一项

用户明确同意后：只改与该项相关的代码与文档。不要顺手做下一项。

项目若有 `AGENTS.md` / 文档约定（勾 TODO、写进展报告、改 ADR），同一轮做完。

完成标准：该项从清单消失或勾掉；约定要写的进展已写；回报按会话索引的报成果形状（能力 → 场景 → 指标前后 → 怎么验）。

### 4. 问要不要下一项

做完问一句是否继续；要继续则回到第 1 步。用户说停就停。
