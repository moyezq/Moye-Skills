# 探针脚本：写不写、留不留

web-crawler 的能力之一。只在「一条命令拿不到、要写脚本」或「本轮收尾」时读（一条 `--raw eval` 就出结果的，不读）。

先试内联；三条全中才落文件；落了的要能原样重跑一次；收尾按四步删干净。

## 目录

1. [先试内联](#先试内联)
2. [落文件的三条](#落文件的三条)
3. [留住的判据](#留住的判据)
4. [收尾四步](#收尾四步)

完成标准（整份）：本轮没有同一件事的第二个同形状脚本；落盘那份带四行头部、本轮原样跑过一次；一次性的已经删掉。

---

## 先试内联

按序试，出结果就停：

1. `--raw eval "…"`：一个值、一个计数、一段 JSON。
2. `run-code` 内联片段：要挂 `page.on('response')` 才看得见的东西。
3. 交互命令直取：`snapshot`、`find`、`cookie-list`、`tab-list`。

```text
✅ 拖一次触发接口，--raw eval 打出状态对象的键，收工
✅ 要拦请求就写 run-code 内联片段，片段留在命令历史里
❌ 三个未知各写一个 .js 落盘，跑完都没删
❌ 同一件事第二版又起一个新文件名
```

---

## 落文件的三条

三条全中才落盘，缺一条就留在命令里：

- 要跑第二遍：换 URL、换站点、回归比对。
- 要给下一次会话或别人跑。
- 有判断逻辑，不是一条 eval 能表达。

落盘时的四行头部，缺一行就不算写完：

```js
// 用途：拿到什么
// 用法：node <路径> <参数>   或   playwright-cli run-code --filename=<路径>
// 依赖：Node 版本、需不需要已开的调试端口、读哪些环境变量
// 输出：写到哪个目录的哪个文件，默认落系统临时目录
```

落点：

| 用途 | 落点 |
|------|------|
| 只在这个项目用的取数工具 | 项目仓 `tools/` |
| 跨项目、本 skill 反复要用的 | 本 skill 的 `scripts/` |
| 只在本机跑一次的探针 | 系统临时目录（`$env:TEMP` / `TMPDIR`），随会话回收 |

---

## 留住的判据

出现任一条就不留：

- 写死调试端口
- 写死 CDP 浏览器 GUID
- 写死绝对输出路径
- `../` 相对导入到别处的代码
- 依赖一个已经停掉的项目

```text
✅ process.env.CAPTURE_PORT || 9222
✅ 输出默认 os.tmpdir()，允许 OUT_DIR 覆盖
❌ ws://127.0.0.1:9222/devtools/browser/<GUID>/ —— GUID 每次启动都变
❌ import(new URL("../lib/foo.js", import.meta.url)) —— 目录一搬就静默失效
```

搬家、改名之后，把留下的那份原样跑一次：跑不动就改到能跑，改不动就删。

---

## 收尾四步

按序做完，四步都算数：

1. 结论落盘：站点结构、接口形状、踩到的坑写进项目 `docs/`。
2. 删一次性脚本；留下的只留第 2 节那三条全中的。
3. 抓包转储、会话副本、`console-*.log`、`page-*.yml` 不进项目目录。
4. 关掉自己起的浏览器和调试连接。

```text
✅ 结论进了项目 docs/，探针留一份在 tools/，临时文件删掉
✅ 抓包落系统临时目录，收尾把那个临时目录删掉
❌ 发布说明写完了，写它用的会话导出副本（几十 MB）还躺在项目旁边
```
