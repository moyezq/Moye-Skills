# 拷问并建文档

无休止地拷问用户，直到达成共享理解。把主题画成一棵 **设计树**：每个决策分出挂在其下的子决策。术语、决策、目标态一结晶就按落点写下，不要等访谈全结束。

## 何时用 / 何时不用

**用**：动手前对齐——爬虫目标（下什么/存哪/去不去水印/番外怎么编号）、脚本形态（单文件还是小服务）、方案选型、字段命名。新系统、多模块、对照实验台：先对齐目标态。用户想被压力测试，或触发词含「拷问 / 盘问 / 先问清楚 / 对齐 / 边问边记」。

**不用**：纯事实查询（直接查）；已经对齐、只剩执行的任务；用户已明确「直接做」且无分支待定。

## 按轮次推进

把树按 **轮次** 处理。**前沿（frontier）** = 所有「前置已解决」的决策，也就是现在就能问、不用猜答案的问题。一轮把整个前沿一次性问完：给每个问题编号，并附上你的推荐答案。等用户回答后再进下一轮。

一轮的格式：

```
❓ **Q1** - **<问题标题>**：<问题正文，可多段，可含多个选项>

➡️ <你的推荐答案>

---

❓ **Q2** - **<问题标题>**：<问题正文>

➡️ <你的推荐答案>
```

用户每轮的回答会重塑树：已解决的决策把前沿往外推，解开依赖它们的后续问题；重新计算前沿问下一轮。**答案依赖本轮其它问题的，属于后面轮次，不要本轮就问。**

## 新系统的第一轮前沿

主题是新系统、多模块、对照实验台、跨会话迭代时，**第一轮只问目标态**，不要先问「第一闭环怎么接」：

1. 系统边界与明确不做
2. 目标模块清单（目标态，不是本轮要实现的）
3. 目录落点与落地形态（单文件 / 多入口 / 小服务）

落地顺序（第一闭环、第一条源、先接哪条在线路径）放在目标态拍板之后的轮次。第一闭环对齐不是树的结束。

单文件脚本、爬虫字段、已有项目的局部选型：不必走这一节，用上面的普通前沿即可。

软件仓目标态落盘见 `self-project-docs` 的 `architecture.md`，目录怎么摆见 `python-standard-coding` 的 `references/project.md`。知识库文的目录落点是笔记路径，不建 `architecture.md`。

## 分工：事实归 AI，决策归用户

**查事实是 AI 的活**，永远不该让用户去查。前沿问题若需要环境事实（文件、工具、接口），派后台 subagent 或用工具去查，别问用户任何你自己能查到的。不阻塞：正在查的是一颗「未解决的前置」，只有它下游的问题等它出结果，其余前沿照问。

**决策归用户**：把每个决策摆到用户面前，等答复。推荐答案用对方已经在用的词。评测黑话（金标、fixture、gold）先改成白话（示例抽取、对照表），除非用户自己先用了那个词。

教学语料、可跑脚本、给人看的图，对齐时摊开（怎么写进笔记不在这里展开）：

- 真实/可查还是虚构：可查则用公开通告、判决、年报；虚构须用户点头。
- 字数、条数是硬上限还是随口一说：随口则公开原文可以更长。
- 复制就能跑：默认可跑路径不依赖 Chat API 或 Key。
- 给人看的结构：静态 HTML（或指定可视化库）还是只落 JSON。

## 沉淀文档

结晶了就写。按落点加载，不要把细则抄进本文件。

- 软件仓沉淀 CONTEXT、adr、architecture、README、AGENTS、最小视图：再加载 `self-project-docs`。
- 笔记库 知识库文：再加载 `self-notes-read`；新建或改结构则接着读其 `references/writing.md`。
- 两处都要沉淀时两份都加载。

## 结束条件

前沿为空、设计树每个分支都走完、没有任何东西被静默假设时，本轮访谈结束。在用户确认达成共享理解前，不要开始动手。该写的文档已按上一节落点写完。

新系统 / 多模块：目标态分支（边界、明确不做、模块清单、目录落点）走完才结束。只把第一闭环问清楚不够。

**进入实现**：对齐结束后按本轮落点动手，本文件不再列实现细则。软件仓多模块：动手前写好目标模块与目录落点；单文件流水线按分阶段脚本切步。知识库文：按笔记查阅 skill 主文件已有的写法与案例指针写。
