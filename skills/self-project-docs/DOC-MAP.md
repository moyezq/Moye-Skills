# 文档地图：建 / 读 / 改 / 守

本文件是 `self-project-docs` 的按需参考。主文件只留职责表；来这里查某一份文档怎么用。

已存在的文件才谈「必须照做」。没建的文件不要假装它在。

---

## CONTEXT.md

叫法。格式见 [CONTEXT-FORMAT.md](./CONTEXT-FORMAT.md)。

- **建**：第一个本项目特有术语结晶时。
- **读**：给字段/类/函数起名之前；用户用了一个可能冲突的词时。
- **改**：叫法定了，或代码让定义过时（例如知识块仍写「用于向量检索」）。同一轮改，不要攒。
- **守**：代码和其它文档用术语表里的词，不另造同义名。
- **不要**：写实现细节、开关名、怎么跑。那是蓝图或 README。

## docs/adr.md 与 docs/HISTORY.md

现行为什么，以及被废决策的变更记录。格式见 [ADR-FORMAT.md](./ADR-FORMAT.md)。

- **建**：第一条够格决策时建 `docs/adr.md`。第一次废决策时建 `docs/HISTORY.md`。不要建 `docs/adr/` 目录。
- **读**：写代码前听蓝图和 `AGENTS.md`。读 `adr.md` 只为仍有效的为什么。`HISTORY.md` 只在问「为什么曾经那样 / 要不要复活」时读。不要把已从 `adr.md` 删掉的选定当禁令。
- **改**：同一条决策改细节则重写该条并改日期；新问题新编号；整条取代或废弃则从 `adr.md` 删掉并追加 `HISTORY.md`。现状句只写实现进度。否定旧选定的那一轮：旧条处理完、蓝图改完，`AGENTS.md` 有引用也改完。
- **守**：不把刻意偏离「修」回常见做法。以 `adr.md` 里**现在**那条为准，不要翻 HISTORY 当现行法。
- **不要**：一决策一个文件；用现状句写新选定；只加新条却让旧选定留在 `adr.md`。

## docs/architecture.md

目标态蓝图。格式见 [ARCHITECTURE-FORMAT.md](./ARCHITECTURE-FORMAT.md)。

- **建**：多入口 / 多模块 / 对照实验台，动手写代码之前。
- **读**：加模块、改目录、按设计文档写下一批代码之前。读的是目标态，不是本轮要实现的范围。
- **改**：模块从「未做」变成「已实现」或「内联」时同一轮改状态表。真正还没做的写进现状缺口，不要把已完成项再写成待办。
- **守**：新代码进落点槽，不另起一摊。明确不做就是不做。第一闭环不是终点。
- **不要**：另建 `PROJECT-SPEC.md` 或 `ARCHITECTURE.md` 重复「绝对不做」和目录结构。不要把现状图、Mermaid、聚焦 HTML 写进本文；那是最小视图。

## docs/overview.md（最小视图）

现状可视化。选型见 [SHOW-FORMAT.md](./SHOW-FORMAT.md)。不是蓝图。落盘规则见主文件「最小视图」。密 UI 用 `docs/overview.html`。模块用 `docs/<模块名>-overview.md`；脚本用同级 `<stem>.overview.md`。

- **建**：clone 无图且用户要看结构；或用户要求留下场景 2/3 的视图。
- **读**：已有则讲结构前先看，避免另画一张打架。
- **改**：现状变了且用户要更新图，覆盖同一文件。
- **守**：讲现状以这份为准；目标态仍听 `architecture.md`。
- **不要**：写进 `architecture.md`；可交互仪表（官方 `canvas`）；场景 2 当轮解释默认落盘；无路径的场景 3 往工作区写 `docs/`。

## README.md

给人跑。正文四块（基础信息、生产与启动、结构、使用说明）见 `self-python-project`。

- **建**：第一条可跑闭环之后，或用户要使用指南。
- **读**：告诉用户怎么跑之前；改端口、入口、环境名之前。
- **改**：端口、入口脚本、conda 环境、密钥怎么注入——和代码同一轮。
- **守**：按它写的方式跑。运行参数在文件顶部常量区就不要假装有 CLI 参数。
- **不要**：当术语表或蓝图用；写还没验证的方案；写会随需求经常变的前端交互边界。未定方案写进 `TODO.md`。

## AGENTS.md

本仓给 AI 的硬规矩：禁止的库、本仓例外、不能自由发挥的点。

- **建**：全局 `self-*` skill 管不到、且本仓会反复踩的禁令出现时（例如禁止某废弃 SDK、禁止把密钥写进仓、禁止给本仓发明 CLI）。
- **读**：本仓写代码之前（文件存在就读）。
- **改**：新的本仓禁令拍板时。
- **守**：本文件压过「换个更流行的库」的冲动。编码风格仍走 `self-python-style` 等 skill，本文件只写**本仓例外**。
- **不要**：把全局 skill 抄进来；没有例外就不要建空文件。

## DESIGN.md

配色、间距、基础交互。

- **建**：UI 超过「一页提问 + 薄 POST」；或用户要定视觉 / 交互规范。
- **读**：改布局、颜色、间距、交互之前。
- **改**：设计 token 或基础交互变了，与界面改动同一轮。
- **守**：界面改动跟它走。实现手法见 `self-frontend`。
- **不要**：薄问答页为「完整」而建一份设计系统。

## TODO.md

分项勾选。权威仍是蓝图；本文件是工作副本。

- **建**：`architecture.md` 目标态已有之后。没有蓝图就不要用 TODO 当设计。
- **读**：从清单挑下一项实现时。
- **改**：做完一项勾一项，且同一轮改蓝图状态。新项必须能在蓝图状态表或现状缺口里找到对应。
- **守**：只做蓝图里有的槽或缺口。冲突时改 TODO 去对齐蓝图，或两份同一轮一起改。
- **不要**：把 TODO 当目标态；一次把清单全做完却不改文档；只写第一闭环就当项目做完。

## 不要另建：PROJECT-SPEC.md

产品目标与「这次绝对不做」写在 `docs/architecture.md` 第 1 节（系统是什么 + 明确不做）。用户要产品规格时读蓝图，不要拆第二份规格。

## docs/COMPONENT-GUIDELINES.md

共享组件规矩与公共 UI 逻辑。

- **建**：至少两处真正复用同一套组件。
- **读**：加或改共享组件之前。
- **改**：共享组件约定变了，与代码同一轮。
- **守**：新的共享 UI 跟它走。
- **不要**：只有 Composer / Thread 一页时拆组件规范。

## docs/PAGE-STRUCTURE.md

多页结构与路由。

- **建**：多于一个路由页面。
- **读**：加页面或改信息架构之前。
- **改**：页面结构变了，与路由改动同一轮。
- **守**：新页面放在它写明的结构里。
- **不要**：单页薄问答为它单开文件。

## docs/DEPLOYMENT.md

打包与上线。

- **建**：真要发布、打包、配生产环境时。
- **读**：发布或改部署配置之前。
- **改**：部署步骤或配置变了，与改动同一轮。
- **守**：发布按它做。
- **不要**：本地 conda + Vite 实验台为它写一份上线文档。
